# EDINET・有価証券報告書・財務諸表

J-Quants の有料プランをやめるための、日本株の財務諸表の取得先。実データで確認した
ことだけを書く。推測は書かない。

株価は立花で埋まった（`docs/TACHIBANA.md`）。埋まらずに残っていたのが**財務諸表の
時系列**で、立花が返すのは比率のスナップショットに留まる。そこがここ。

## なぜ有報なのか

有価証券報告書の冒頭にある「主要な経営指標等」に、**1本で5期ぶん**の連結と単体が
入っている。売上・純利益・自己資本・総資産・ROE・発行済株式数。1社につき年1件
落とすだけで、5年分の財務時系列が無料で手に入る。

## 確定していること（すべて実データで確認済み）

観測対象は3社。いずれも2026年3月期。

| 銘柄 | 会計基準 | docID | 最上段の収益 |
|---|---|---|---|
| 日立製作所 6501 | IFRS | `S100YGBO` | 売上収益 |
| 三菱UFJ 8306 | 日本基準（銀行） | `S100YJQO` | 経常収益 |
| JR東日本 9020 | 日本基準（鉄道） | `S100YC7N` | 営業収益 |
| トヨタ 7203 | IFRS | `S100Y8NY` | **連結の売上が表に無い** |

| 項目 | 値 |
|---|---|
| 書類本体 | `https://api.edinet-fsa.go.jp/api/v2/documents/{docID}` |
| 認証 | 目録と同じ。`Subscription-Key` クエリ＋`Ocp-Apim-Subscription-Key` ヘッダ |
| `type=1` | iXBRL 一式の ZIP。3.7 MB・86ファイル |
| `type=2` | PDF |
| `type=5` | **XBRL を CSV に変換したものの ZIP。243 KB・3ファイル** |
| `type=5` の中身 | `XBRL_TO_CSV/jpcrp…csv`（本体）＋ `jpaud…csv` 2本（監査報告書） |
| CSV の形式 | **UTF-16LE + BOM、タブ区切り、全項目を引用符で囲む、CRLF** |
| 本体 CSV の行数 | 6501 は 2,776 行（「主要な経営指標等」160行、`jpdei` 27行） |
| ZIP の大きさ | 6501 は 243 KB、8306 は 285 KB |
| 有報の `docTypeCode` | `120`。訂正有報は `130` |

`type=5` があるので、**XBRL の構文解析は要らない**。これが実装量を桁で変えた。

### 断られても HTTP 200 で返る

EDINET は拒否した要求にも 200 を返し、本文だけを JSON のエラーにする。転送層は
何も言わない。`fetch_document` は本文の先頭が `PK`（ZIP）かどうかを自分で見る。
見ないと、下流が「ZIP ではありません」と言うだけになり、鍵が無いのか書類が無いのか
分からなくなる。

## 数字を取り違える8つの罠

どれも**例外は出ない**。5期ぶんのそれらしい表が出てきて、中身が違う。

### 1. 連結と単体が同居し、区分の列では見分けられない

「連結・個別」列は連結の行にも単体の行にも「その他」を入れる。実際に分かれて
いるのは**コンテキストID**で、単体には `_NonConsolidatedMember` が付く
（`CurrentYearDuration_NonConsolidatedMember`）。

日立で取り違えるとこうなる。

| 項目 | 連結 | 単体 | 差 |
|---|---:|---:|---:|
| 当期純利益 | 8,023億 | 7,840億 | 2% |
| 自己資本 | 65,683億 | 39,491億 | **40%** |
| 総資産 | 150,412億 | 69,326億 | **54%** |
| ROE | 12.9% | 20.8% | **1.6倍** |

要素名でも見分けられるように**見える**。IFRS 適用会社では連結が
`…IFRSSummaryOfBusinessResults`、単体が `…SummaryOfBusinessResults` になっていて、
日立ではコンテキストによる分類と 32要素すべてで一致した。**だがこれは IFRS 適用
会社に限った話で、日本基準の会社は連結も単体も同じ要素名を使う。** そこでは名前は
何も教えてくれず、コンテキストIDだけが残る。だからまずコンテキストで絞り、名前の
優先順位は第二の防御線として残してある。

連結財務諸表を作っていない会社（子会社が無い）は連結の行が1つも無い。そのときだけ
単体に落ちる。

### 2. 発行済株式数は「連結」で絞ると消える

`TotalNumberOfIssuedSharesSummaryOfBusinessResults` には**常に**
`_NonConsolidatedMember` が付く。連結の株式数という概念が無く、提出会社そのものの
事実だから。財務項目と同じ理屈で弾くと、株式数の列だけが空欄になる。`ENTITY_FIELDS`
はこのためにある。

### 3. EPS だけが分割調整済み

発行済株式数と1株配当は**当時のまま**。日立の前々期（2024年の1:5分割の前）で
純利益 ÷ EPS を取ると 46.5億株だが、報告されている発行済株式数は 9.27億株。
ちょうど 5.01 倍ずれる。

配当性向を「1株配当 ÷ EPS」で出すと **141.8%**。同じ有報が報告している値は
**28.8%**。どちらの数字も単体では正しい。

**1株当たりの値どうしを、年をまたいで割ってはいけない。** `AnnualFigures` は
絶対額と報告された比率しか持たず、`FinancialReport` の `eps` / `bps` /
`dividend_per_share` は空のままにする。

### 4. 相対年度は「当期」と「当期末」が別

期間の項目（売上・利益・ROE）は `当期`、時点の項目（自己資本・総資産・株式数）は
`当期末`。片方のラベルだけで探すと、その列が丸ごと空になる。

| 期間 | 時点 |
|---|---|
| 四期前 | 四期前時点 |
| 三期前 | 三期前時点 |
| 前々期 | 前々期末 |
| 前期 | 前期末 |
| 当期 | 当期末 |

### 5. 最上段の収益は業種で名前が変わる。銀行に売上高は無い

三菱UFJの有報には `NetSalesSummaryOfBusinessResults`（売上高）が**1行も無い**。
銀行の最上段は**経常収益** `OrdinaryIncomeSummaryOfBusinessResults`（60,758億）。

| 業種 | 要素名 | 項目名 |
|---|---|---|
| 一般事業会社（IFRS） | `RevenueIFRSSummaryOfBusinessResults` | 売上収益 |
| 一般事業会社（日本基準） | `NetSalesSummaryOfBusinessResults` | 売上高 |
| 証券・不動産など | `OperatingRevenue1SummaryOfBusinessResults` | 営業収益 |
| 銀行・保険 | `OrdinaryIncomeSummaryOfBusinessResults` | 経常収益 |

1社の中で年をまたいで名前が変わることはないので、成長率は正しく出る。業種を
またいだ「売上の絶対額」の比較は元から意味を持たない。

**トヨタは IFRS なのに `RevenueIFRS…` を持たない。連結の売上が表そのものに無い。**
表にある売上高 `NetSales…`（12.6兆）は提出会社単体で、連結は48兆前後。4社目にして
初めて `NetSales…` が実データに現れたが、それが連結だったのは1社も無い。取れない
ものは空にする――単体を代わりに入れれば、成長率も PSR も別の会社の話になる。

連結の売上がどこにあるかは未解決。`type=5` の CSV は有報**全体**（日立で2,776行）
なので、財務諸表本体には必ず載っている。ただし本体は当期・前期の2期ぶんしか無く、
5期の時系列は「主要な経営指標等」からしか取れない。

### 「主要な経営指標等」の要素ファミリーは1つではない

日立の**提出会社単体**の売上収益は `RevenueKeyFinancialData` にしかない
（18,431億）。`…SummaryOfBusinessResults` だけを見ていると、このファミリーに
しか無い項目が丸ごと落ちる。列が空欄になるだけで例外は出ない。

| ファミリー | 日立での要素数 |
|---|---:|
| `…SummaryOfBusinessResults` | 32 |
| `…KeyFinancialData` | 1（`Revenue` のみ） |

両方を読む。連結で絞る処理はその後なので、日立では単体の 18,431億 は取られず
連結の 105,868億 が残る。

**同じ要素名が、会社によって連結と単体のどちらにも付く。** 営業収益
`OperatingRevenue1…` は JR東日本では**連結**（19,790億）、三菱UFJでは**単体**
（6,226億）。優先順位だけで選ぶと、三菱UFJで連結の経常収益 60,758億 の代わりに
単体の営業収益 6,226億――10分の1――を掴む。先にコンテキストで絞るのは、この
ためでもある。

**`OrdinaryIncome…`（経常収益）と `OrdinaryIncomeLoss…`（経常利益）は別物で、
同じ表に並んでいる。** 三菱UFJで 60,758億 と 15,376億、4倍違う。要素名の比較は
名前空間を落とした**完全一致**にしてある。部分一致だとここで事故る。

### 6. 日本基準の連結純利益は別の要素名

`NetIncomeLossSummaryOfBusinessResults` は日立でも三菱UFJでも**提出会社単体**の
欄だった。日本基準の連結は
`ProfitLossAttributableToOwnersOfParentSummaryOfBusinessResults`
（親会社株主に帰属する当期純利益）。三菱UFJで 11,308億 対 5,718億、2倍違う。

どちらを取ったかは、有報が報告している ROE で裏が取れる。連結
11,308億 ÷ 自己資本 179,882億 = 6.3%、報告値は 6.7%（期中平均を使うので少し高い）。
単体 5,718億 なら 3.2% にしかならない。

### 7. 未記載は全角ダッシュで来る。0 ではない

JR東日本の2022年3月期は最終赤字で、配当性向も PER も `－` が入っている。0 として
取り込むと、配当性向 0%・PER 0倍の**割安株**として画面に出る。`-` `－` `―` と
空文字を、数値ではないものとして扱う。

赤字の年は符号も落とさない。連結 **-949億**、ROE **-3.9%**。

### 8. 要素名が意味を保証しない

日立の `EquityToAssetRatioIFRSSummaryOfBusinessResults` の項目名は
**「１株当たり親会社所有者帰属持分（IFRS）」= BPS** で、値は 897.78 円。
自己資本比率ではない。同じ有報の `EquityToAssetRatioSummaryOfBusinessResults` の
ほうは本当に自己資本比率（0.454）。EDINET は会計基準ごとに別の概念へ同じ名前を
使い回している。名前で選ぶときは項目名と値の桁を必ず確かめること。

## 決算年度の決め方

表には相対年度しか書いていない。`jpdei` の `CurrentFiscalYearEndDateDEI`
（日立は `2026-03-31`）から1期につき1年ずつ遡って割り当てる。

年度は**決算日の年**。J-Quants 側が `FYEnd` の年を使っているので、揃えておかないと
同じ決算期が `(security, fiscal_year, period)` の一意キーで別行になる。3月期の
2026-03-31 は 2026年度。12月期の 2025-12-31 は 2025年度。

決算期を変更した会社ではずれる。有報の表は相対年度しか持たないので、1本の有報から
分かるのはここまで。

銘柄コードも `jpdei` にあるが**5桁**で、末尾は株式の種別（日立は `65010`）。
落とさないと watchlist の `6501` と噛み合わない。

## 使い方

```
uv run stock-ai statements 6501 --source edinet
```

`.env` に `JP_STATEMENT_SOURCE=edinet` と書けば `--source` なしで切り替わる
（`JP_PRICE_SOURCE` と同じ形）。既定は `jquants` のまま。

有報は年に1度しか出ないので、探す窓は既定で **400日**。1日1リクエストだが、日ごとの
応答は `EdinetDisclosureSource` が抱え込むため、同じインスタンスを使い回せば銘柄が
何本あっても走査の費用は変わらない。逆に1銘柄だけのために呼ぶと400リクエスト掛かる。

訂正有報（`130`）も候補に入れている。訂正のほうが後から出るので、新しい日から
探せば自然に勝つ。順序を決めているのは書類の型ではなく**提出日**。

## まだ確認していないこと

- **連結の売上を持たない有報（トヨタ）をどう埋めるか**。「主要な経営指標等」の
  外――財務諸表本体――に落とせば取れるが、本体は2期ぶんしか無い。5期の時系列と
  混ぜると、古い3期だけ売上が空く形になる。
- **連結の売上高 `NetSales…` を持つ会社**。4社読んで、連結側に現れたことが一度も
  ない。日本基準の製造業（7267 ホンダ、6758 ソニーなど）で確かめたい。
- **営業利益**。日本基準には `OrdinaryIncomeLossSummaryOfBusinessResults`（経常利益）、
  IFRS には `ProfitLossBeforeTaxIFRSSummaryOfBusinessResults`（税引前利益）がある。
  **この2つは別物**なので、`FinancialReport.operating_income` に混ぜて入れていない。
  どちらか一方に寄せるか、列を分けるかは決めていない。
- **総資産と ROE は保存していない**。`AnnualFigures` は読むが、
  `FinancialStatement` にその列が無いので `to_reports` で落ちる。ROE は
  純利益 ÷ 自己資本 で戻せるが、総資産はスキーマを足さないと持てない。
- **四半期**。四半期報告書（`140`）にも「主要な経営指標等」があるが、見ていない。
- **複数の `jpcrp` CSV**。`S100YGBO` には1本しか無かった。2本以上ある有報が
  存在するかは分からない。あった場合は警告して先頭を使う。
- **EDINET はこの開発環境から到達できない**（403 CONNECT）。立花と同じく Windows
  側で実行して結果を見ている。
