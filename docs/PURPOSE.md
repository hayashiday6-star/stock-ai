# stock-ai の目的

**ユーザーが 2026-09-16 に示した文書。** ここが、すべての判断の帰着先である。
`CLAUDE.md` は「どうやるか」を書いた場所で、**「何のためか」はここにしかない。**

## 一言で

世間で語られる投資の定説・アノマリー・都市伝説と、それらを組み合わせた複合型を、
日本株と米国株で事前登録つきで検証し、実際のリターンを計算する。
合格した説だけを自動売買に載せる。不合格の説も検証過程ごと公開する。

## 分類（各説にタグを付ける）

- 種類:
  - `technical` … 価格・出来高だけで条件を計算できる説（例: ゴールデンクロス、新高値ブレイク）
  - `fundamental` … 財務・開示データが必要な説（例: 低PBR、増配、上方修正）
  - `anomaly` … 暦・需給・俗説など上の2つに入らない説（例: Sell in May、節分天井彼岸底）
- 構成: `single` / `composite`（composite は構成要素の種類をすべて併記）
- 市場: `jp` / `us`

## 1本の説の流れ（既存フローを踏襲）

1. `docs/HYPOTHESES.md` に登録（ID、種類、構成、市場、出典、説の主張を一文で。
   composite は構成要素IDも）
2. 既存ひな形で `docs/PREREG_<ID>.md` を作成。§0 検出可能性ゲートを通過したものだけ、
   リターン計算前に封印
3. IS → OOS の順に実行。封印後に基準を変えない
4. 判定は「合格 / 不合格 / 検出できず / 検証不能」のいずれかで `HYPOTHESES.md` に記録
5. 判定に関係なく公開用レポートを `reports/<ID>/` に出力
   （出典、条件、封印日、結果表、図、見つかった実装欠陥、結論）
6. 合格のみ `PaperBroker` で紙トレードに進む。実運用に移すかは人間が判断する

## 複合型のルール

- 構成要素は `HYPOTHESES.md` に登録済みの説をIDで参照する
- 組み合わせ方（AND条件、スコア合算、重み）は封印時に固定する。
  **成績を見ながら組み合わせを探さない**
- 構成要素ごとの単独成績も、同じ期間・同じ条件で同時に計算する
- **合格には、最良の構成要素単独を上回ることを必須とする**
- 試した組み合わせは1通りにつき1本として累計本数に数える
- AND条件はイベント数が急減するため、§0ゲートで件数と流動性の内訳を必ず確認する

## 守ること

- **不合格も成果。** 合格に寄せるための事後の条件変更はしない
- 検証した説の累計本数を `HYPOTHESES.md` で数え、合格判定では多重検定を考慮する
- **上場廃止銘柄を含める**（生存バイアスを入れない）
- **取引コスト込み**のリターンで判定する
- データ制約で検証できない説は代替データで無理に進めず「検証不能」として理由を残す

## データ源

- 日本株: 価格＝立花証券API（2001年〜）、財務＝EDINET有報、
  銘柄一覧＝立花マスタ＋日付別名簿（git管理）
- J-Quants は解約済み（2026-09-15 に Free へ）。**会社予想・開示時刻が必要な説は
  取得済みの範囲に限る**
- 米国株: データ源は未定。**決まるまで米国の説は登録のみで実行しない**

## 作業の進め方

- 新しい説に着手する前に、既存の検証基盤（gap-continuation、disclosure-impact など）
  から流用できる部品を確認する
- **実装前に計画を提示し、承認を得てから書く**
