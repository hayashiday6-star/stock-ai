# 立花証券・ｅ支店・ＡＰＩ

J-Quants の有料プランをやめるための、日本株の株価取得先。実データで確認した
ことだけを書く。推測は書かない。

## なぜ替えるのか

J-Quants の無料プランは **2年分・直近12週間は取得不可**。screen も monitor も
3ヶ月前の株価で判断することになり、**エラーは出ずにそれらしく間違う**。

立花は口座があれば無料で、6501 で **6,279件・2001-01-04 〜 2026-08-21** が
返った。25年半で、当日まで来ている。いま払っている J-Quants の5年より長い。

## 確定していること（すべて実機で確認済み）

| 項目 | 値 |
|---|---|
| 専用ＵＲＬ | `https://kabuka.e-shiten.jp/e_api_{版}`（検証は `demo-kabuka`）。**版を固定値で埋めないこと**、下記参照 |
| 公開鍵の登録形式 | **X.509 SubjectPublicKeyInfo の PEM**、BEGIN/END 行を含めてそのまま |
| 鍵の条件 | RSA、2048 または 4096 bit、SHA-256（画面の注記） |
| 仮想ＵＲＬの暗号 | **RSA-OAEP（MGF1-SHA256 / SHA256, label なし）**。平文末尾に改行が付くので落とす |
| 送信方法 | 既定 POST（本文が JSON 文字列、`Content-Type: application/json`）。GET も可で、その場合 `?` の後ろは**生の JSON**（percent-encode しない） |
| 文字コード | **ShiftJIS** |
| 必須の共通項目 | `p_no`（要求ごとの通番）、`p_sd_date`（`.000` 固定）、`sJsonOfmt`（`"5"`） |
| エラー判定 | 2段。伝送層 `p_errno`/`p_err` → 業務層 `sResultCode`/`sResultText` |
| 仮想ＵＲＬの寿命 | 当日限り。`p_no` とともに保存して使い回す |
| 時価配信の口 | `sUrlEventWebSocket` だけ `wss://` で返る |

## 版の寿命 — 固定値で埋めてはいけない

版はパスの Prefix (`e_api_vNrN`) にあり、**旧版は後継の並行リリースから
およそ60日で停止する**。埋め込むと、停止日から「原因不明の通信エラー」として
現れる。日付から解決し、期限が近づいたら自分で警告する作りにしてある。

| 版 | 公開 | 停止 |
|---|---|---|
| v4r9 | 2026-05-16 | **2026-09-27** |
| v4r10 | **2026-08-29** | 未定 |

`"v4r10" > "v4r9"` は文字列比較では**偽**になる。数値で比べること。

### v4r10 で何が変わるか

公式のお知らせ（2026-08-18）によれば、**マスタ等情報の取得方式が、従来の
Ｉ／Ｆから「各個別情報毎問合取得Ｉ／Ｆ」に変わる**。負荷低減が目的とされている。

これは我々に有利に働く。v4r9 の銘柄マスタは `CLMEventDownload` による配信で、
応答を返さず `CLMEventDownloadComplete` まで受け続ける必要があった。v4r10 では
通常の問合せになるため、**株価と同じ作りで書ける**。

並行リリース期間中、v4r9 も動くが追加機能は使えない。v4r10 のマニュアルは
2026-08-29 以降に公開される。**銘柄マスタは v4r10 で実装する。**

## 株価履歴 `CLMMfdsGetMarketPriceHistory`

1要求1銘柄。**日付範囲の指定が無い**ので、毎回全期間（25年分）が返る。

### `xK` 列の正体

これが本実装の要。マニュアルの「始値ｘ分割係数」という説明だけでは決まらない。

**`xK` = raw × （その日より後にある分割係数すべての積）**

つまり **現在の株数単位に直した、分割調整済みの系列**。6501 の実データで、
**25,116個の価格と6,279個の出来高すべてが一致**した（不一致 0 件）。

6501 の分割イベントは2つで、互いに打ち消し合うため見誤りやすい:

| 日付 | 分割前→後 | 係数 | 前日終値 → 当日終値 |
|---|---|---|---|
| 2018-09-26 | 5 → 1（株式併合） | 5 | 777.8 → 3894 |
| 2024-06-27 | 1 → 5（株式分割） | 0.2 | 17620 → 3654 |

- 2018-09-26 より前: 後続の係数の積 = 5 × 0.2 = **1.0** → `xK == raw`
- 2018-09-26 〜 2024-06-26: 積 = **0.2** → `xK == raw / 5`
- 2024-06-27 以降: 後続なし → `xK == raw`

**両端だけを見ると `xK == raw` なので「調整されていない」と読み違える。**
実際に一度そう読み違えた。中間期間（1,401行）を見ないと分からない。

### DB へのマッピング

解析層（`factor_test`、`portfolio/factors`、`portfolio/analysis`、
`seasonality`）はいずれも `adj_close` を読む。したがって:

| DB 列 | 立花の項目 | 理由 |
|---|---|---|
| `open` / `high` / `low` / `close` | `pDOP` / `pDHP` / `pDLP` / `pDPP` | 実際に取引された価格 |
| `adj_close` | `pDPPxK` | 分割調整済み。リターンと factor はこちらを読む |
| `volume` | `pDV` | |

### 差分更新をしてはいけない

`xK` は**最新の分割を基準にした相対値**なので、新しい分割が起きると
**過去の行の値が遡って変わる**。追記型の更新では、分割をまたいだ瞬間に
古い行だけ古い基準のまま残り、系列が不連続になる。

日付範囲を指定できず毎回全期間が返る仕様とも合わせて、**取得のたびに
その銘柄の系列を丸ごと置き換える**のが正しい。

### 全銘柄を回すコスト（実測 2026-09-03、5銘柄から外挿）

| | 値 |
|---|---|
| 1銘柄あたり | **1.23 MB / 0.21 秒**（約 6,200 本、25年分） |
| 3,607 銘柄 | **4.4 GB / 13 分** |
| 要求間隔 0.5 秒 | 43 分 |

**解約の障害にならない。** 外挿は線形で、DB書き込み・再試行・レート制限は
見ていない。

### データの質（6501, 6279件）

- 日付の重複なし、昇順、OHLC の整合崩れなし
- 出来高 0 の日が 1 日ある
- **価格は小数を取りうる**（raw で 1,041行、xK で 2,275行）。整数として
  読んではいけない
- 非分割日には `pSPUO` / `pSPUC` / `pSPUK` の**キー自体が存在しない**（空文字ではない）

## 銘柄マスタ — v4r10 で要求形式が確定（2026-09-03）

**仮想ＵＲＬは `sUrlMaster`。** 株価履歴の `sUrlPrice` とは別の口である。
要求は機能ＩＤだけで、全銘柄が1回で返る。

マスタ機能の1〜13番はシステム稼働中に更新されないので、**1営業日に1回取れば
足りる**。

### `CLMStkGetIssueMstKabu`（株式銘柄マスタ）

```json
{"sCLMID": "CLMStkGetIssueMstKabu"}
```

応答は `aCLMStkIssueMstKabu` の配列。J-Quants の代わりになりうる項目：

| 項目 | 中身 | 何の代わりになるか |
|---|---|---|
| `sIssueCode` | 銘柄コード | — |
| `sIssueName` / `sIssueNameEizi` | 銘柄名（和文・英文） | 銘柄名 |
| `sZyouzyouHakkouKabusu` | **上場発行株数** | `ShOutFY`（時価総額の分母） |
| `sGyousyuCode` | **業種コード（33業種）** | セクター |
| `sBaibaiTani` | 売買単位 | 発注単位 |
| `sBaibaiTeisiC` | 売買停止Ｃ（9=停止中） | — |

業種コードは `0050` 水産・農林業 から `9050` サービス業、`9999` その他まで、
東証33業種がそのまま入る。

### `CLMStkGetIssueSizyouMstKabu`（株式銘柄市場マスタ）

```json
{"sCLMID": "CLMStkGetIssueSizyouMstKabu"}
```

応答は `aCLMStkIssueSizyouMstKabu` の配列。

| 項目 | 中身 | 何の代わりになるか |
|---|---|---|
| `sZyouzyouKubun` | **上場区分** 01プライム / 02スタンダード / 09グロース | 市場区分（`Segment`） |
| `sSinkiZyouzyouDay` | 新規上場日 | 上場日 |
| `sZyouzyouHaisiDay` | **上場廃止日** | **J-Quants にも無かった** |
| `sSinyouC` | 信用Ｃ（1貸借 / 2制度 / 3一般） | 空売り可否 |
| `sNehabaMin` / `sNehabaMax` | 値幅制限 | ストップ高安の判定 |

### 実測（2026-09-03、本番、v4r10）

どちらのマスタも **4,441 件**で、銘柄コードで1対1に対応する。

| 上場区分 `sZyouzyouKubun` | 件数 |
|---|---|
| 01 プライム | 1,555 |
| 02 スタンダード | 1,555 |
| 09 グロース | 596 |
| 00 それ以外（ETF・REIT など） | 543 |
| 21 TPM | 187 |
| 03/04/11 外国銘柄 | 5 |

3区分の合計 3,706 は東証の公表値とほぼ一致する。**業種コードの空は 1 件だけ。**

**★上場廃止日は使えなかった。** 4,441 件中 **4,418 件が空**で、値が入って
いるのは 23 件だけである。廃止済み銘柄がマスタに残っているのではなく、現存
銘柄に廃止予定日が入っているだけだった。**生存バイアスは是正できない。**

「マニュアルに項目がある」ことと「過去のデータが取れる」ことは別である、という
例がまた1つ増えた。

もう1つ実測で分かったこと。**立花は「値が無い」を空文字ではなく半角スペースで
返すことがある**（`sBaibaiTeisiC` が 4,255 件そうだった）。`str` として真だから
という理由で通すと、空白を意味のある区分値として扱ってしまう。

### 銘柄コードは4桁とは限らない

プライムの件数が見込み 1,556 に対して 1,549 だったので調べたところ、**7件が
5桁コードだった。**

```
25935  50765  75505  92015  92025
```

すべて5桁で末尾が `5`、先頭4桁は既存の普通株コード（2593 / 5076 / 7550 /
9201 / 9202）である。**優先株・種類株に割り当てられる番号で、普通株ではない。**
ユニバースから落ちるのが正しい。

`1,556 − 7 = 1,549` で件数が合う。

**ログの出し分けに注意する。** 正しい除外を毎回 WARNING で出すと、本物の警告が
見えなくなる。5桁は INFO、それ以外の桁数は WARNING にしてある。

### そのほか、J-Quants の無料プランに無いもの

| 機能ＩＤ | 中身 |
|---|---|
| `CLMMfdsGetIssueDetail` | **予想EPS `pEPSF`**・予想PER・実績BPS・PBR・ROE・配当利回り・**配当権利落日 `pCLOE`**・年初来高安。最大120銘柄/回 |
| `CLMStkGetDateZyouhou` | **営業日カレンダー**（前3営業日・翌10営業日・株式受渡日） |
| `CLMMfdsGetShinyouZan` | 信用残（一般/制度/合算、前週比、信用倍率）。最大120銘柄/回 |
| `CLMMfdsGetSyoukinZan` | 証金残（融資・貸株・差引・回転日数・貸借倍率）。最大120銘柄/回 |
| `CLMMfdsGetHibuInfo` | 逆日歩。最大120銘柄/回 |
| `CLMMfdsGetNews` | ニュース（過去90日、**銘柄コード紐付き** `p_ISL`、本文は ShiftJIS の BASE64） |

`pEPSF` は「一株利益（予想・通期連結）」なので、**J-Quants の `FEPS`（会社
予想EPS）の代わりになる可能性がある。** ただしスナップショットであって
時系列ではない。過去の予想は遡れない。

## 使い方

`.env` に1行入れると、日本株の株価取得先が全体で切り替わる。

```
JP_PRICE_SOURCE=tachibana
```

単発で切り替えるなら `--source`。銘柄が市場を決め、市場が取得先を決めるので、
米国株が混じっていても自動で yfinance に回る。

```
uv run stock-ai fetch 6501 7203 --source tachibana
```

必要な設定は `TACHIBANA_AUTH_ID`（`.env`）と秘密鍵ファイルだけ。版と接続先は
既定で解決するので、通常は書かなくてよい。

## 実データが暴いた、立花以前からの欠陥

25年分を入れた最初のバックテストで、**戦略もテクニカル指標もエンジンも、未調整の
`close` / `open` を読んでいた**ことが分かった。分割日に価格は不連続に飛び、下流には
暴落と区別がつかない。エラーは出ず、数字だけが変わる。

J-Quants でも同じだった（`AdjustmentClose` を `adj_close` に入れていたが、誰も読んで
いなかった）。過去5年に分割した日本株のバックテストは、すべて誤っていたことになる。

6501 での実測:

| | 修正前 | 修正後 |
|---|---|---|
| 分割をまたぐ2ヶ月の買い持ち | **-80.14%** | -0.72% |
| 25年の sma200 | **-8.99%** | **+373.54%** |
| 25年の買い持ち・最大DD | -84.71% | -83.01% |
| 25年の sma200・最大DD | -83.84% | -39.96% |

**sma200 の評価が反転した。** 価値を毀損する戦略に見えていたものが、買い持ちと同等の
リターンを半分以下のドローダウンで出していた。

ただし上表は**手数料もスリッページもゼロ**での値で、この戦略は25.6年に103回売買する。
現実的なコストを入れると像が変わる:

| 手数料/回 | スリッページ | リターン | 最大DD |
|---|---|---|---|
| 0% | 0% | +373.54% | -39.96% |
| 0.10% | 0.05% | +248.18% | -42.59% |
| 0.20% | 0.10% | +156.01% | -46.08% |
| （買い持ち・1回） | | **+400.58%** | -83.01% |

往復0.15%程度で**リターンは買い持ちに負ける**。残る優位はドローダウンだけで、正しい
言い方は「リターンを2〜3割譲る代わりに下落幅を半分にする戦略」。しかも1銘柄・
インサンプルなので、優位性の証拠ではない。`factor-test` の walk-forward を通すまでは
何も主張できない。

25年の買い持ちの**リターンだけ**は偶然正しかった。6501 は2018年の5倍併合と2024年の
0.2倍分割が打ち消し合い、両端では調整の有無が一致する。既存の635件が捕まえられ
なかったのも同じ理由で、区別できるのは分割をまたぐ期間だけであり、テストの価格系列に
分割は無かった。

修正は `PriceRepository.get_prices` で `adj_close / close` を全OHLCに掛ける。呼び出し元
ではなく取得側に置いたのは、呼び出し元が十数箇所あり、一箇所忘れれば同じ欠陥が戻る
ため。**最新のバーでは係数が必ず 1.0** になる（その後に分割が無い）ので、現在値を読む
処理は影響を受けない。

## J-Quants を完全に外すのに残る穴

株価と銘柄マスタは立花で埋まる。埋まらないのは**財務諸表の時系列**だけで、
立花が返すのは比率のスナップショット（PER/PBR/ROE/EPS/BPS/配当利回り）に留まる。

そこは **EDINET** で埋めた。有価証券報告書の「主要な経営指標等」に1本で5期ぶんが
入っており、`documents/{docID}?type=5` は XBRL を CSV に変換したものを返すので
構文解析も要らない。実データで確認したことは `docs/EDINET.md` にまとめてある。

```
uv run stock-ai statements 6501 --source edinet
```

残っているのは、日本基準の会社で要素名が同じかどうかの確認だけ
（`9-EDINET財務確認.bat`）。

## まだ確認していないこと

- **信用残・証金残・逆日歩**（`CLMMfdsGetShinyouZan` 等、120銘柄/回）。
  J-Quants の無料プランには無いデータ。まだ叩いていない。
- **`bulk-fetch` を立花で全銘柄回したときの実挙動**。所要時間は実測した
  （下記）が、DB書き込みと再試行を含めて通しで走らせてはいない。
- **要求の間隔に上限があるか**。マニュアルにも公式サンプルにも記載を
  見つけていない。

## 秘密の扱い

- `tachibana_private.pem` — 仮想ＵＲＬを復号する秘密鍵。`.env` と同じ扱い
- `tachibana_session.json` — 当日の仮想ＵＲＬが**復号済みで**入る。これ自体が
  資格情報で、持っていればその日の口座機能を叩ける
- `TACHIBANA_AUTH_ID` — `.env` に置く

いずれも `.gitignore` 済み。プローブは認証ＩＤも仮想ＵＲＬも指紋しか表示しない。
