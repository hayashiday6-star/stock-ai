## §1. 仮説

**増担保規制がかかった銘柄は、規制の公表後に負の超過リターンを示す。**

### 機構

**規制は強制的な取引を作る。** 増担保がかかると委託保証金率が引き上げられ、

1. 新規の信用買いが実質的に止まる（買い手が減る）
2. 既存の買い建て玉が、追加の保証金を差し入れられずに解消へ向かう（売りが出る）

**需給の向きが、値動きとは独立な理由で決まる。** 「誰も見ていないから残る」型
ではなく、**「知られているが制約があるので残る」型**である。規制を知っている
人でも、追証を避けるための売りを止められない。

### この型を選んだ理由

前者の型（誰も見ていない）は、7本試して7本落ちた。**後者の型は、効果が消える
条件が違う。** 消えるとすれば「規制を見越して先回りする人が十分に増えたとき」
であって、そのときは**公表日より前に動きが出る**——それは測れば分かる（§5 の
副次指標に置く）。

**これは 2026-09-08 に踏んだ形そのものである**——市場区分を「最後に見えた姿」
で引いて、当時 TOKYO PRO だった銘柄を「スタンダード」と読んだ。例外は出ず、
もっともらしい値が出るだけだった。

## §3. 並べ替えと分位

**並べ替えない。** 分位に割らず、**発動したイベントを等加重で持つ**単一の束と
して測る。

### なぜ分位にしないのか

規制の発動は**二値の出来事**であって、強弱の順序が無い。無理に順序を作れば、
その作り方が1つの自由度になる。**イベント型でそれをやると、並べ替え方の選択が
結果を左右したのかどうかを後から切り分けられない。**

### 保有窓 — リターンを見ずに決める

> **窓 N ＝ 規制が解けるまでの営業日数の中央値**（IS 期間で測る。上限20営業日）。

`jquants_margin.onsets()` が発動日を、`REGULATION_RELEASED`（`101`）が解除を
持っている。**発動から解除までの日数は、リターンを1つも見ずに測れる。**

機構が言っているのは「規制が効いているあいだに強制的な売りが出る」なので、
**規制が効いている期間そのものが窓である。** これは後付けの理屈ではなく、
§1 の機構から直接出る。

上限を20営業日に置くのは、既存の登録（#3、#6）と揃えるためと、**中央値が
極端に長い（例：解除されない銘柄が多い）場合に窓が発散しないように**である。

**中央値を見て、そこから窓を選び直さない。** 上の式で機械的に決まる。

## §4. 売買ルール

| | 決めたこと |
|---|---|
| イベント日 D | **`PubDate`（公表日）** |
| エントリー | **D+1 営業日の始値** |
| エグジット | **D+N 営業日の終値**（N は §3） |
| 建玉 | 1イベント1単位、等加重。**ショート** |
| 費用 | 往復 0.4%（`reversal.COST_ROUND_TRIP`）。**仮定ではなく既存の実測値を引く** |

### `AppDate` を使わない

配布サンプルでは**適用日 2023-07-04 の行が 2023-07-05 に公表**されている。
**適用日でイベントを置くと先読みになる。** 売買できるのは公表日以降である。

**#2 で開示時刻を巡って解いたのと同じ形がここにもある。** 向こうは「15時前の
開示か後か」、こちらは「適用日か公表日か」で、**どちらも1日ぶんの先読みで、
どちらも例外は出ない。**

### 費用について、いま言えないこと

増担保のかかる銘柄は投機的な売買が集まっている。**スプレッドや逆日歩が平常
より重い可能性がある。** ここで置いた 0.4% は**他の設計から引いた値**であって、
この母集団で測った値ではない。

§13 に、**入れ替え率から出し直した費用**を併記する。**判定の基準は 0.4% の
ままにする**——見てから上げるのも下げるのも事後的である。

## §5. 評価指標

**主要指標：発動イベントの、市場対比の平均リターン（D+1 始値 → D+N 終値、
費用差引後）。符号は負を期待する。**

**主要指標は1つだけである。** 発動側のみ。

### 副次指標（**判定には使わない**）

| | 何が分かるか |
|---|---|
| 解除イベントの同じ測り方 | 逆向きに出るか。**出なくても発動側の判定は変わらない** |
| D−5 〜 D の値動き | **公表より前に動いているか。** 先回りが増えていれば、ここに出る |
| 日々公表のみ（規制なし）の同じ測り方 | **機構が効いているのは規制のほうか**の切り分け |
| 入れ替え率から出し直した費用 | §4 |

**副次を判定に使わない理由。** 使えば基準が2つ以上になり、多重検定になる。
#4（決算集中日）を「親の説が落ちたので判定しなかった」としたのと同じ規律で
ある。

## §6. 期間分割

| | 期間 | 用途 |
|---|---|---|
| 推定（IS） | 原本の覆う期間の前半 | **分散・窓・見込みのみ。平均は判定に使わない** |
| 判定（OOS） | 後半 | **一度だけ** |

`end` は「この日より後のデータを1つも使わない」という意味で実装する。
**イベント日だけで切ると、保有期間が越えて伸びる**——D+N が OOS の外に出る
イベントは、D が中にあっても使わない。

## §7. 生存バイアス

**日付ごとの名簿がある。** `data/universe_daily/` に 2021-09 以降の全営業日
ぶん（1,227枚）があり、Premium の週に20年ぶんへ伸ばす。

**`margin-alert` は10年ぶんなので、名簿のほうが長い。** 名簿の無い期間に
イベントは無いので、ここでの制約にはならない。

**判定と診断で同じ universe を使う。** #7 は判定を db universe で回し、診断を
名簿ありと生存者のみで回したので、**判定がその2つのどちらにどれだけ近いかを
測れなかった。** ここでは両方とも「その日の名簿 ∩ 貸借銘柄 ∩ 流動性下限」で
回す。

バイアスの実測には**標準誤差と t も出す。** 平均だけ出すと、0 と区別が付くのか
分からないまま次の登録に引用されていく。

## §9. 主張できないこと

- **日々公表への指定の効果ではない。** 測るのは増担保規制のほうである。
  両者は別物で、JPX の一覧でも ※ で区別されている。
- **実際に空売りできたかは、貸借区分までしか見ていない。** 逆日歩・品貸料・
  貸株の在庫は見ない。**「貸借銘柄である」と「その日に借りられた」は別である。**
- **規制の強さの違いは見ない。** `TSEMrgnRegCls` には2次・3次・4次規制の別が
  あるが、**分けて測れば基準が増える。** 発動を二値として扱う。
- 10年より前のことは言えない。`margin-alert` がそこまでしか無い。

## §10. 中止条件（**判定を回さずに閉じる**）

1. **原本に規制の別が無い。** Premium の週に取った `/markets/margin-alert` に
   `Restricted` も `TSEMrgnRegCls` も無ければ、機構が言っているイベントを
   取れていない。**日々公表への指定に置き換えない**——それは別の説である。
2. **§0 を通らない。** 見込みの下限が検出できる差に届かない。
3. **IS の下限が 1.2% を下回る。** 上に書いたしきい値。
4. **貸借銘柄と流動性の下限を通した後、OOS のイベント数が §0 の要求期数に
   届かない。**

**どれか1つでも当たれば封印しない。** 閉じた理由を `docs/HYPOTHESES.md` に
専門用語なしで書く。

## §11. 合格基準と読み方の表（**結果を見る前に確定**）

主要指標は負を期待するので、**符号を反転した値**（＝ショートの取れ高）で
当てはめる。

| ショートの取れ高 | t | 読み方 |
|---|---|---|
| ≤ 0% | — | 効果なし。閉じる |
| 0% 〜 0.4%（費用） | — | 費用を賄えない。閉じる |
| 0.4% 〜 検出できる差 | t < 2.0 | **構造的な帯。** 不合格だが「効果が無い」ではない |
| 0.4% 〜 検出できる差 | t ≥ 2.0 | 合格 |
| ≥ 検出できる差 | t < 2.0 | 点推定は十分だが有意でない |
| ≥ 検出できる差 | t ≥ 2.0 | **合格** |

**この表は人が当てはめるのではなく、コードが当てはめる。** 判定が出てから
基準が動きかけた前例がある。

## §12. 合格したときに何をするか（**封印前に決める**）

| | 決めたこと |
|---|---|
| 持ち方 | イベントごとに等加重のショート。同時に持つ本数に上限は置かない |
| レバレッジ | **無し。** 信用の余力の範囲に収める |
| 比率 | 1イベントあたり、口座の 2% を上限とする |
| **判定基準に含めない記録項目** | **最大下落・勝率・保有本数の推移。** 含めれば2つ目の基準になり、多重検定になる |

**合格しても、増担保のかかった銘柄をショートするのは、逆日歩の当たる側である。**
実行に移す前に、**逆日歩の実測を別に取る**（判定には含めない）。
