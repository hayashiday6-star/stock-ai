# 自動売買の運用モニタ(「自動売買 運用」画面)

stock-ai のダッシュボードに、**別リポジトリで動いている自動売買システムの運用画面**を
足したもの。移植元は、その自動売買リポジトリに同梱されていた Streamlit の操作パネル
(`app.py` / `app_lib.py`)。

## どこが正典か

| もの | 場所 |
|---|---|
| 自動売買の実行(cron・シグナル・発注・照合) | WSL `Ubuntu-24.04` の `~/test` |
| 帳簿(`positions.json` ほか)・キルスイッチ・通知設定 | 同上 |
| この画面 | stock-ai(Windows 側) |

stock-ai は **売買しない**。この画面は正典を読みに行くだけで、売買ルールも帳簿の
解釈も stock-ai 側には置いていない。

参照先は `.env` の `OPS_WSL_DISTRO` / `OPS_REPO_PATH` / `OPS_REPO_PYTHON`。
既定は `Ubuntu-24.04:/home/hayashida/test`。

## なぜ「読みに行く」のか(ロジックを写さない理由)

60日高値ブレイク・出来高1.5倍・20日持ち切りといった条件や、帳簿の読み方を stock-ai
側に書き写すと、片方だけ直したときに **もっともらしいが違う値が黙って出る**。この
プロジェクトで繰り返し起きているのはまさにその種類の不具合で、画面に出た数字が実運用
と違うことは、数字を見ているだけでは気付けない。

そこで、シグナルも帳簿も資産推移も、**正典の `app_lib` にそのまま計算させる**。
仕組みは単純で:

1. `stock_ai/ops/_payload.py` の中身を `wsl.exe` 経由で正典の Python に標準入力で渡す
2. その Python が正典の作業ディレクトリで `app_lib` を呼ぶ
3. 結果を JSON で1個だけ標準出力に書き、Windows 側が読む

渡すのは**固定のコマンド名**(ホワイトリスト)と JSON 引数だけ。発動理由やメモのような
自由入力は `shlex.quote` を通してから載せるので、シェルのコマンドとしては解釈されない。

## できること・できないこと

できる(6ビュー):

- **状態** — キルスイッチ・cron の本数・broker と運用資金・保有・翌営業日の注文・ログ末尾
- **資産推移** — 帳簿とキャッシュ済み日足から再計算した日次時価評価(3トラック)
- **売買履歴** — 全トラックの売買を新しい順に、戦略ルールから導いた「根拠(自動)」つきで
- **通知設定** — Discord 通知のイベント別 ON/OFF
- **検証(ドライラン)** — シグナル条件を変えて、何が買い候補になるかを見るだけ
- **運用操作** — キルスイッチの**発動**、定時ジョブの手動実行

できない(意図的に作っていない):

- 実発注(発注に触れるのは正典の `MANUAL_JOBS` の **ドライラン固定**のものだけ)
- 帳簿(`positions.json`)の変更、broker 切替、リスク上限の変更
- **キルスイッチの解除** — 原因を特定したうえで、ユーザー自身が正典側でファイルを消す。
  この層に解除の口は無い(`tests/test_ops.py` がその不在をテストしている)

書き込むのは、移植元の操作パネルが元々書いていた3つだけ:
通知設定(`notify_config.json`)・売買メモ(`trade_notes.json`)・キルスイッチの発動。

## 画面を開かずに確かめる

```bash
uv run stock-ai ops --what check     # 参照先が生きているか
uv run stock-ai ops --what status    # キルスイッチ・cron・保有
uv run stock-ai ops --what history --limit 20
uv run stock-ai ops --what equity    # 3トラックの時価評価(数十秒)
uv run stock-ai ops --what jobs
```

`ops` は読み取り専用。発動と保存は画面にしか置いていない。

## うまくいかないとき

- **「正典リポジトリを参照できません」** — WSL が止まっている可能性が高い。
  `wsl -d Ubuntu-24.04 -- true` を一度実行してから再読み込みする。
- **参照先が違う** — 画面上部と `stock-ai ops --what check` に、実際に見ている
  `distro:path` が出る。古いコピー(例: `Desktop\claudecode`)を指していないか確認する。
- **資産推移が遅い** — 正典側で parquet を読み直すため数十秒かかる。画面では10分
  キャッシュしている。「再読み込み」で捨てられる。
